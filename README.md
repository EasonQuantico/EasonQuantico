# 个人主页 · Scuderia 赛道终端

一个零依赖、单仓库部署的个人主页与线上简历系统。视觉取意 F1 车队（法拉利红 × 碳纤黑 × 遥测仪表盘）+ 终端/ASCII 排版语言；功能保留访问门禁、云端同步的分享动态与浏览器内管理后台。

- GitHub Pages 镜像：<https://easonquantico.github.io/EasonQuantico/>

## F1 赛道模拟器

首页右侧面板里的内置小游戏：俯角 60° 的「车顶朝前」跟随相机，随机赛道循环，10 辆车同场竞速。

- **比赛形式**：页面加载即进入**自动驾驶**（玩家车与 9 辆 AI 同场跑圈、遥测与排行榜全速运行），点 `Play` 才接管为手动；**接管后自动驾驶永久关闭**，`Quit` 后重新发车也是手动，不会再自行接管。玩家车（`YIP` / CAR 16）与 9 辆对手各有独立涂装（车色 / 侧箱 / 头盔 / 前翼饰条）
- **赛道生成**：极角随机多边形（11–15 个顶点，半径在 0.40–1.00 之间交替、部分角间距收窄到 0.55 倍）→ 先按目标周长 1500–1820 m 整体缩放 → 顶点用**绝对半径**（15–41 m）圆弧倒角，切线长受相邻边长约束（≤ 0.42·短边，两端倒角不会互相吃掉）→ 4 m 均匀重采样 → 三重几何校验：① 曲率 ≤ 1/13.2 m（弯心半径必须大于 8.1 m 半路宽，否则内缘翻折）；② 非相邻路段（沿赛道 > 40 m）中心线间距 ≥ 26 m（路面全宽 16.2 m + 余量，杜绝路面重叠）；③ 周长 / 凸包周长 ≥ 1.05（太圆说明没有大角度弯，丢弃）。任一项不合格就整条重抽，**不再用「局部平滑 / 整体放大」去凑曲率**（那会把发夹弯压扁、把 1.4 km 的赛道拉成 2.3 km）。实测 24 条：单圈 1.29–1.68 km、8–12 个弯、其中转向 ≥ 65° 的大角度弯 3–7 个、最小间距 28–39 m、合格率 100%，生成耗时中位数 1.8 ms（最坏 6.4 ms）；每完成一圈立刻换一条新赛道
- **玩法**：`←` `→` 转向，`↑` 加速，`↓` 制动。**纵向动力学**用「踏板行程 + 扭矩曲线 + 空气阻力」建模：油门/刹车都是 0→1 的行程量，踩下按 14 / 20 /s、松开按 17 / 24 /s 逼近（约 0.2 s 到 95%），点按不会瞬间全油；引擎推力 22.5 m/s²，扭矩按 `1 −(v/101.8)^1.6` 衰减（中段更饱满），风阻 `0.34 + 0.00020·v²`，松油只剩 1.25 m/s² 滑行阻力，制动力 48 m/s² 并在 3.2 m/s 以下线性收力——实测 **0–100 km/h 1.6 s、0–200 3.8 s、0–300 7.8 s、极速 345 km/h、345→0 刹停约 2.0 s**。**与 AI 的差距**：对手加速度上限 11.6 m/s²（约为玩家一半）、制动上限 26 m/s²、目标极速 0.94·TOPV（约 90 m/s），所以同样一脚油门玩家 1 s 多冲 13.7 m/s、对手只有 11.3 m/s，刹车更是 47 vs 26 m/s² —— 出弯和制动区能明显拉开/追近。速度越快离心外抛越强，压路肩掉速，撞护栏闪光震动并按 620 ms 冷却扣速，护栏同时会把车往赛道里推，不会卡死在墙上
- **视角**：针孔透视投影，相机位于车顶上方 17.5 m、朝车头方向俯视 60°，可视距离约 100 m；路面、路肩、砾石缓冲区、护栏立柱与反光片、起跑格、胎胶痕、小地图逐帧重绘
- **小地图**：右下角 132×132 逻辑像素（原 92），锚点不变（右边距 12 / 下边距 18），赛道先描 5 px 暗底再叠 1.9 px 高亮线，玩家点带红环、对手点按车队色区分
- **赛车**：不用 3D，用「固定高度 y 的平面多边形 + 同一投影」分层叠加（由低到高：投影 / 底板 / 悬挂 / 轮胎 / 前翼 / 侧箱 / 单体壳 / 座舱与 Halo / 尾翼），按屏幕尺寸做三级 LOD（远车只画剪影），近车带胎壁配方色环、Halo 支柱、后视镜、雨灯。俯视机位下车身容易被透视拉长，因此车体局部坐标再乘一组比例修正（横向 ×1.26、纵向 ×0.88），并把鼻锥加钝，避免「窄长」观感。**可见性剔除**：相对距离按闭环折返取到 ±半圈内（原先跨起点线会算成 −1800 m 被剔除，刚过线的车凭空消失），且屏幕底边本身能看到相机身后约 6.4 m 的路面，所以身后 6.4 m 内的车照常绘制，只会随画面底边滑出而不是突然消失
- **实时排行榜**：画面左侧 10 行计时塔，按赛道位置（累计圈速）排序，显示名次、车队色条、车手代码、**最佳圈速**（全场最快标紫）、**落后领先车的秒差**（用两车均速折算，避免过弯时跳变）；未跑完首圈时该列显示本圈进行时并以半透明区分。每 180 ms 刷新一次，玩家所在行高亮。跑出个人最佳圈时会把三段时间存为基准，本圈 S1/S2/S3 旁显示 ± 差值（更快绿、更慢红）
- **控制**：`Play` / `Quit` 按钮进出入；运行中方向键被 `preventDefault` 接管，不会滚动页面，退出后页面滚动恢复；焦点在输入框 / 文本域时自动让行（后台编辑表单里打字不会被当成转向）。画面离开视口、切换标签页、失焦自动暂停（手动模式需点 `Resume`；自动驾驶静默暂停、回到视口自动继续）
- **车队无线电**：冲出白线或被其他车碰到时，左下浮出仿 F1 转播图形的字幕卡 —— 深色卡面 396:250，左上角是裁切的头盔特写（矢量剪影 + 斜向渐隐，模拟转播素材图），右侧红色 `YIP` 叠白色大号 `RADIO` 右上对齐，左下 24% 卡宽的大红 `16`，右下法拉利盾，底部一条红渐变字幕带显示 `I am stupid...`。整卡用 `container-type:size` + `cqw` 等比缩放，宽度由 JS 按「画布高度 − 排行榜占位」实时计算（上限 214 px），所以从 1680 到 360 px 版面里卡片始终贴在排行榜下方、按比例收缩；如果某档画面太矮压到了排行榜，会加 `.rd-over` 把排行榜淡到 22% 让位。3.4 s 冷却防连环刷屏、2.3 s 自动收起
- **提示卡（Race Notes）**：游戏区上方一叠与无线电字幕卡同款视觉语言的卡片 —— 深色卡面 + 左沿红条 + 小尺寸头盔剪影 + 红色 `YIP` / 白色 `RADIO` + 大红 `16` + 法拉利盾 + 底部红渐变字幕带（带引号，两行内截断）。多条文案会**堆叠**：首张完整显示，后面两张以 -13 px / -24 px 偏移 + 缩放 + 降透明度露出卡片上沿（只留边缘、不显示文字，避免叠影）；**自动循环**按设定间隔（默认 4.2 s，可选 3 / 4.2 / 6 / 9 s 或关闭）把首张送上去、下一张接位，底部一条 1 px 进度发丝线跟随间隔走完；鼠标悬停 / 页面隐藏时暂停，点击卡片可手动切下一条，右下角 `01/03` 显示序号。文案在后台「赛道提示卡 / Race Notes」维护：可新增（≤120 字）、点击「编辑」改某一条、`↑ ↓` 调顺序、`✕` 删除，最多 8 条，全部写入 `localStorage`；云端可用时整组 JSON（`{v:2,items,gap,ts}`）写进 `tag=__simnote` 的保留配置行（`link_text` 存毫秒时间戳），页面加载按时间戳取较新的一份，老版本的纯文本单条记录会自动兼容为一条卡片。该配置行在分享卡片查询里被过滤，不会混进作品卡片堆
- **性能**：仅在运行中跑 `requestAnimationFrame`，暂停即停；画布按 devicePixelRatio 缩放并限制 DPR ≤ 2；单帧约 40 个路面采样点、300 次投影、沥青颗粒用一次性预渲染的 64×64 图案平铺

## 技术栈

- **前端**：原生 HTML / CSS / JavaScript，单文件实现，零框架、零构建
- **视觉资产**：无背景视频、无位图纹理；赛道模拟器为 Canvas 2D 矢量绘制（透视投影 + 程序化赛道），其余全部由 CSS 渐变/遮罩绘制
- **分享卡片媒体**：卡片为固定宽高比（桌面 1.34、≤680px 0.82、≤380px 0.74），媒体区占满剩余高度，图片/视频以 `object-fit:contain` 整幅等比呈现——不裁切、不变形、卡片内不出现滚动条；左右留白用同图模糊衬底补齐，无配图的卡片改为刻度网格 + 幽灵序号
- **主题色**：`#e10600`（Rosso）/ `#070506`（碳纤黑）/ `#f6f0ea`（暖白），等宽字体承担 HUD 标签与数字
- **云端**：WorkBuddy Cloud Service（PostgreSQL + 行级安全 RLS + Origin 校验），前端经 CDN SDK 读写
- **部署**：GitHub Pages（`main` 分支根目录，提交后自动重建）+ WorkBuddy Cloud Service（分享动态的云端数据，不可达时前端自动降级为本地模式）
- **字体**：系统字体栈（含思源/苹方/雅黑回退）+ 等宽字体栈（JetBrains Mono → Cascadia → Consolas），零 Web Font 请求
- **无障碍**：`prefers-reduced-motion` 下关闭动效并保留首帧（游戏可玩，仅关闭屏幕震动与撞击闪光）；按钮与画布均有可读标签，正文语义结构完整

## 数据架构

分享动态使用云端数据库表 `share_posts`：

```
id BIGINT PK | tag | date | title | body | link | link_text | media_data | media_kind | sort_order | created_at
```

- **RLS 策略**：匿名可读可写（SELECT/INSERT/UPDATE/DELETE 全放行），配合数据面 **Origin 强制校验**限制写入来源——仅应用注册域名可通过，GitHub Pages 等外部来源的请求会被拒绝
- **前端数据流**：优先云端拉取 → 云端不可达时显示 `OFFLINE · 本地模式`，回退 localStorage / 内置默认数据；云端空表时自动播种默认内容
- **写入路径**：管理后台的所有增删改直接写云端，刷新即全网可见
- **媒体存储**：`media_data` 存完整 data URI（`data:image/*` 或 `data:video/*` 的 base64），`media_kind` 标记渲染方式。选择存库而非对象存储的原因：WorkBuddy Storage 仅对登录用户开放且无公开 URL，而分享媒体需要匿名可见；data URI 复用现有公开读通道，且 GitHub 镜像站也能加载。限制：图片 ≤6MB、视频 ≤24MB（前端校验），本地缓存超配额时自动剥离媒体重试

## 安全模型（如实说明）

- 两道密码（进站门禁 / 管理后台）**互相独立**，源码中只存 SHA-256 哈希 + djb2 兜底哈希，**无任何明文**
- 密码验证在前端完成，验证通过后写入 sessionStorage（会话级）
- **已知局限**（均为静态站点的物理边界，非实现缺陷）：
  1. 前端哈希校验可被懂行者绕过（关闭 JS、直接调用接口）；Origin 校验依赖请求头，非密码学鉴权
  2. 短密码的哈希可被暴力还原——建议使用长密码，或迁移到服务端鉴权
  3. 门禁页logo 为视觉设计的一部分，访客可见

## 更新流程

修改内容后需同步三个发布面：

1. **改 `index.html`**（源文件，一切改动从这里开始）
2. **重建单文件版**：`python build_standalone.py`（资源 base64 化 + PDF 链接改写为运行时 Blob）
3. **部署**：`python deploy_pages.py` 提交到 GitHub（Pages 自动重建，约 20 秒生效）

> 说明：本地 git 在非交互环境可能因凭证助手或传输问题失败（`fetch-pack: invalid index-pack output`），因此部署改用 GitHub Git Data API，只依赖已登录的 `gh` CLI。

## QA 方法

- headless Chrome（`--dump-dom` + 注入测试脚本）走**真实 UI 路径**：点击按钮 → 填写表单 → 触发 submit → 断言 DOM 状态
- 多断点视觉验证：桌面 / 平板 / 390px 手机（注意：headless Chrome 窗口宽度下限约 500px，真机小屏需 iframe 外壳模拟）
- 云端回路验证：线上「插入 → 读回 → 删除」完整闭环，测试数据用后即删
- 密码泄露扫描：全仓库大小写不敏感扫描明文，甄别 base64 随机子串误报
